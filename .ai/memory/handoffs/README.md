# Handoffs Memory

Store concise continuation context for unfinished, blocked, interrupted, or transferred work.

## Store Here

- Current objective and confirmed state.
- Active task and plan paths.
- Work completed and files changed.
- Exact validation already performed and observed results.
- Remaining work in priority order.
- Blockers, unresolved decisions, risks, and warnings.
- The exact next recommended action.

## Do Not Store

- Full conversation history.
- Large logs or complete source files.
- Easily rediscovered repository facts.
- Unverified assumptions presented as facts.
- Secrets or sensitive data.

## Naming

Use a stable name such as `YYYY-MM-DD-task-name-handoff.md`.

## Template

Use `/templates/handoff-template.md`.

## Lifecycle

Handoffs are historical continuation records. Create a new handoff when state changes materially rather than rewriting old evidence.
