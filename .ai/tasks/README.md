# Tasks

Task records are the operational source of truth for active work.

## Lifecycle

- `inbox/`: proposed or unrefined work.
- `active/`: work that has a clear objective and is currently being executed.
- `completed/`: work that satisfies the Definition of Done.
- `templates/`: reusable task and bug templates.

## Task Requirements

Every active task must include:
- Objective
- Scope
- Acceptance criteria
- Relevant context
- Risks or constraints
- Validation requirements
- Current status

Blocked work remains in `active/` and must record the blocker, impact, owner, and next action.
