# Design Documentation

Design documents define product experience, visual language, interaction patterns, accessibility, and content standards.

## Files

- `design-system.md`: reusable UI principles, tokens, components, states, forms, tables, navigation, responsive behavior, and accessibility expectations.

## Usage

- Read this area before implementing user-facing interfaces.
- Align UI changes with established components, states, and content style.
- Update design guidance when a new reusable pattern is introduced.

## Quality Standard

- Interfaces must support loading, empty, error, permission, and success states where relevant.
- Components must be responsive and accessible.
- Design documentation should guide implementation decisions, not describe decoration.
