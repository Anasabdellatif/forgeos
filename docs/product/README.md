# Product Documentation

Product documents define what the project should achieve and how success is measured.

## Files

- `vision.md`: durable product direction, target users, value proposition, principles, non-goals, and success measures.
- `requirements.md`: authoritative functional and non-functional requirements with acceptance criteria and traceability.

## Usage

- Read `vision.md` when making scope, prioritization, or UX trade-offs.
- Read `requirements.md` before implementing user-visible behavior or public/internal contracts.
- Link approved requirements to tasks, plans, tests, releases, and decisions.

## Quality Standard

- Requirements must be observable, testable, and traceable.
- Proposed requirements must not be treated as approved scope.
- Product documents should explain user or business value, not implementation details.
